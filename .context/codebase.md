## Live meeting

1. Control starts or joins the meeting and records session membership in Redis. Realtime calls the internal validation route before accepting each WebSocket. The session registry tracks connected users, and the transport decides whether a slow socket can receive an STT partial. Finals and alerts use the normal send path.
2. The desktop native mixer emits frames with a channel tag, little-endian timestamp, and PCM samples. The desktop capture feature sends tagged PCM to realtime. Realtime sends each channel to a separate Deepgram stream and persists audio to object storage. The STT connection owns socket generations and timestamps, with utterance assembly in a separate accumulator.
3. STT publishes raw finals and partials. Meeting mode consumes finals, attributes speakers, merges utterances, and publishes enriched transcript events. Realtime forwards live events from Redis to the session's sockets. The desktop projects the events into its transcript, alerts, and overlay.
4. The analysis engine runs either the default legacy tier sequence or live decision analysis. Live inference runs with bounded concurrency. Publication can happen as soon as an alert is ready, while commit order keeps state updates in arrival order. Legacy gating, the cost manager, transcripts, and event compatibility each have their own source owner.

## Setup and post-meeting processing

- Control schedules brief jobs and can generate a brief on demand. The brief job runs in workers and uses meeting mode's shared brief generator. [Schedule](../apps/control/src/features/meetings/briefs/brief-schedule.ts) and [brief worker](../apps/workers/src/jobs/pre-meeting-brief/pre-meeting-brief.worker.ts).
- Ending a meeting updates the control state and snapshots session context. Realtime finalizes the recording when the host leaves. The transcribe job reads stored audio, correlates speakers, saves the transcript, and enqueues summary. The summary job persists records and publishes `meeting_processed`. Desktop review loads the results from control. [Session cleanup](../apps/control/src/features/meetings/sessions/session-cleanup.ts), [transcribe](../apps/workers/src/jobs/transcribe), [summary](../apps/workers/src/jobs/summary), and [review](../apps/desktop/src/features/meetings/review).
- Producers and workers use named queues in [the jobs package](../packages/jobs/src/queues.ts). The [meeting handoffs](../packages/jobs/src/meeting-handoffs.ts) own the shared brief and summary payloads and job names. If a wire value appears in multiple services, check the existing Redis or job contract before editing it.

## Configuration owners

Start with [the env example](../.env.example). Control owns the database and auth configuration. Realtime owns socket and control API URLs. The desktop build uses `VITE_CONTROL_URL` and `VITE_WS_URL`. [Meeting mode's env file](../packages/meeting-mode/src/env.ts) owns the default legacy mode, live concurrency, model timeouts, merge timing, and speculative opt-in. [STT's env file](../packages/stt/src/env.ts) owns Deepgram settings. [Object storage configuration](../packages/infra/s3/index.ts) is shared between capture and workers.
